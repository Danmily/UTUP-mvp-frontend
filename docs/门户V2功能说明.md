## 0. 全局规则

### 0.1 标签状态（前台只展示三种）

| 前台状态 | 包含的内部情况 | 判定依据 | 能否加入待选择清单 / 申请 | 卡片展示 |
|---|---|---|---|---|
| **可申请** | 从未申请；申请被拒绝；权限已过期 | 无有效权限，且没有审批中的申请 | ✅ 可以 | 无角标 |
| **已申请** | 已提交，审批中 | 有门户申请记录，审批未结束 | ❌ 不可以（审批通过或被拒绝前不能重复申请） | 右下角斜挂蓝色「已申请」 |
| **可使用** | 当前有有效权限（含门户上线前已有的权限） | 实时权限接口返回有效 | ❌ 不需要 | 右下角「去使用」 |

- 前台**不展示**「已拒绝」「已过期」「需线下对接」等内部状态；所有标签都走线上申请。
- 前台**不展示**标签枚举值 / 示例值，也不展示历史案例的收益数值。

### 0.2 依赖与风险

| 依赖 | 用途 | 现状 | 风险 |
|---|---|---|---|
| 实时权限接口（用户 × 标签） | 判定「可使用」、有效期、过期 | 可查询 | 需确认接口延迟 |
| Triton 审批状态 | 区分「审批中」和「被拒绝」 | ❗ 门户读不到（Triton 不推送；按单号查询需要把接口账号加进审批人） | **上线阻塞项**，Demo 中为假设 |
| 待选择清单存储 | 跨设备保留用户挑选的标签 | Demo 存在浏览器本地 | 上线需改为服务端按用户存储 |

## 1. 多选功能接入

### 1.1 整体流程：先挑后提

| 阶段 | 位置 | 用户动作 | 结果 |
|---|---|---|---|
| ① 挑 | 标签广场 / AI 智能搜索 / 圈人 Agent | 单个或批量把标签加入「待选择清单」 | 只加入清单，**不提交申请** |
| ② 提 | 待选择清单 | 勾选后「批量申请」或「批量移除」 | 每个标签独立建单、独立审批 |

例外：标签详情里保留「直接申请」，用于只想申请一个标签的场景。

### 1.2 加入待选择清单的入口

| 入口 | 操作 | 规则 | 状态 |
|---|---|---|---|
| 标签详情 | 「加入待选择清单」/「直接申请」 | 已在清单中时按钮显示「已加入 · 查看待选择清单」 | ✅ |
| 标签广场列表视图批量勾选 | 切到「列表」→ 勾选 → 底部栏「加入待选择清单（n）」（卡片视图不支持） | 见 1.3 | ✅ |
| 列表视图 | 每行「加入待选择清单」/「直接申请」 | 与卡片规则一致 | ✅ |
| AI 智能搜索 | 每个推荐标签「+ 加入清单」；「核心标签加入待选择清单」 | 只加入可申请的标签 | ✅ |
| 圈人 Agent | 执行前发现缺权限，点「一键申请权限」 | 只带入受控 / 高敏且可申请的标签 | ✅ |

**加入后的反馈**：停留在当前页，弹出提示「已加入 n 个标签 · 去查看清单 →」，点击链接跳到清单页。✅

### 1.3 标签广场批量选择规则（仅列表视图）

> 10/8 与研发评审结论：**卡片视图不做勾选**，保持干净；批量勾选只在**列表视图**和 **AI 智能搜索**提供。

| 规则项 | 规则 | 状态 |
|---|---|---|
| 卡片视图 | 不出现勾选框和「批量选择」按钮；点卡片看详情，单个加入在详情中完成 | ✅ |
| 列表视图 | 第一列常驻勾选框，无需进入「批量模式」；表头勾选框选择本页可申请的标签 | ✅ |
| 适用范围 | 关键词搜索、来源域 / 分级 / 状态筛选后，切到列表即可勾选 | ✅ |
| 可勾选条件 | 状态为「可申请」且不在清单中 | ✅ |
| 不可勾选 | 已申请 / 可使用 / 已在清单：不显示勾选框（已在清单显示「已加入」） | ✅ |
| 行点击 | 点击行打开标签详情；只有勾选框负责勾选 | ✅ |
| 跨页保留 | 列表内翻页、修改筛选时已勾选的保留并累计 | ✅ |
| 底部栏 | 有勾选时出现：「已选 n 个」+ 前 2 个标签名（可单独取消）+「取消选择」+「加入待选择清单（n）」 | ✅ |
| 批量动作 | 广场内**只能加入清单**，不能直接批量申请 | ✅ |
| 切回卡片 | 清空列表中的勾选 | ✅ |
| 浮动入口 | 底部栏出现时隐藏右下角「待选择清单」浮动按钮 | ✅ |

### 1.4 待选择清单

| 规则项 | 规则 | 状态 |
|---|---|---|
| 入口 | 顶部标签页「标签广场 ｜ ✦ AI 智能搜索 ｜ 待选择清单 n」；右下角浮动按钮；加入提示中的链接 | ✅ |
| 展示形式 | 整个内容区切换为清单页，**按行展示** | ✅ |
| 列 | ☑ ｜ 标签名称 ｜ 分级 ｜ 口径描述 ｜ 来源域 ｜ 操作（不展示状态列：能加入清单的默认都是可申请） | ✅ |

### 1.5 提交申请

| 规则项 | 规则 | 状态 |
|---|---|---|
| 表单 | 单个与批量共用一张表单；公共用途默认用于全部标签，可逐项单独设置 | ✅ |
| 使用场景 | 下拉只展示场景名（如「营销投放」）；场景自带标准使用说明，折叠展示并随申请提交 | ✅ |
| 补充说明 | 选填；填写后追加在标准说明之后 | ✅ |
| 建单 | 每个标签独立建单、独立审批 | ✅ |
| 提交后 | 成功项从清单与勾选中移除；部分失败时只重试失败项 | ✅ |
| 状态变化 | 提交成功 → 「已申请」；拿到权限 → 「可使用」 | ✅（依赖 0.2） |

### 3.2 资产接入（单个录入 + 批量导入）

> 状态：✅ Demo 已实现（供给方 / 平台管理员视角 →「资产接入」）；上线需接入飞书通讯录、元数据服务与服务端存储。
> 目标：供给方把资产规范地登记进门户，支持后续**批量导入标签**，直接提升 Q4「资产挂载渗透率」。
> 表单只包含「基础展示」「责任溯源」「密级与状态」三组字段；审批方式、消费约束（允许场景、有效期、导出、脱敏、配额）本期不纳入。

#### 3.2.1 字段定义

**① 基础展示**

| 字段（导入列名） | 页面名称 | 必填 | 类型 / 取值 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `tag_id` | 标签 ID | 是 | 字符串 | 全平台唯一；仅字母、数字、下划线；导入时用于识别新增 / 更新 | `age_seq_v3` |
| `tag_name` | 标签中文名 | 是 | 字符串 | ≤ 50 字 | 近30日下单序列 |
| `description` | 业务口径描述 | 是 | 文本 | 写明业务含义与加工逻辑，≥ 10 字 | 近 30 天下单类目序列，T+1 更新 |
| `coverage` | 覆盖率 | 是 | 百分比 | 0–100，最多 1 位小数 | 82.4% |
| `timeliness` | 时效类型 | 是 | 枚举 | `1` = 离线，`2` = 实时 | 1 |
| `update_freq` | 更新频率 | 条件必填 | 枚举 | 见 3.2.2 联动规则 | T+1 |

**② 责任溯源**

| 字段（导入列名） | 页面名称 | 必填 | 类型 / 取值 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `owner` | Owner（个人） | 是 | 飞书账号 | 必须是有效的 lark-id | @zhangsan |
| `owner_team` | Owner Team | 是 | 字符串 | — | 电商 DMP 团队 |
| `source_system` | 上游系统 / 来源域 | 是 | 枚举 | 电商DMP / 生服LDMP / AI用户画像 / 双域算法资产（决定标签广场的来源域筛选） | 电商DMP |
| `source_table` | 来源表 | 是 | 字符串 | `库名.表名` 格式 | ecom_dmp.dwd_user_active |
| `source_field` | 来源字段 | 是 | 字符串 | 必须是来源表中存在的字段 | order_cate_seq |

**③ 密级与状态**

| 字段（导入列名） | 页面名称 | 必填 | 类型 / 取值 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `table_security` | 表密级 | 是 | 四级枚举 | 开放（L2）/ 通用（L3基础）/ 受控（L3高）/ 高敏（L4） | 受控 |
| `column_security_level` | 列密级 | 否 | 四级枚举或空 | 该字段有单独列密级时填写；没有则留空 | 高敏 |
| `effective_column_level` | 最终生效密级 | —（系统计算） | 四级枚举 | **不可填写**，见 3.2.2 | 高敏 |
| `status` | 上线状态 | 是 | `online` / `off` | 新建默认 `off`，审核通过后变为 `online` | online |

#### 3.2.2 联动与计算规则

| 规则 | 说明 |
|---|---|
| 时效 → 更新频率 | `timeliness = 2`（实时）时，`update_freq` 自动为「实时」，不可修改；`timeliness = 1`（离线）时，`update_freq` 必填，只能选 T+1 / T+7 |
| 最终生效密级 | `effective_column_level = max(table_security, column_security_level)`；列密级为空时等于表密级。密级从低到高：开放 < 通用 < 受控 < 高敏 |
| 与门户分级的关系 | 标签广场展示的「统一分级」取 `effective_column_level`，申请审批也按它走 ❓ |
| 上下线 | `online`：在标签广场可见、可申请；`off`：标签广场不可见，已有权限不受影响 ❓ |

#### 3.2.3 资产上传 SOP

| 步骤 | 执行人 | 动作 | 产出 / 状态 |
|---|---|---|---|
| 1. 准备 | 供给方 | 确认资产已在来源表落地，明确 Owner、口径、表 / 列密级 | — |
| 2. 获取模板 | 供给方 | 资产接入页「下载导入模板」（Excel / CSV，列名即 3.2.1 的字段名，含填写说明与示例行） | 模板文件 |
| 3. 填写 | 供给方 | 一行一个标签；单个资产也可直接在页面表单填写 | 填好的模板 |
| 4. 上传校验 | 供给方 | 上传文件，系统逐行校验（见 3.2.4） | 校验报告 |
| 5. 预览修正 | 供给方 | 查看每行结果：✅ 新增 / 🔄 更新 / ❌ 错误；错误行可在线修改或下载错误清单改后重传 | 全部行通过 |
| 6. 提交审核 | 供给方 | 提交通过校验的行；状态为「待审核」，`status = off` | 待审核 |
| 7. 审核上线 | 平台管理员 ❓ | 审核口径与密级；通过后 `status = online`，同步到标签广场 | 已上线 |
| 8. 下线 | 供给方 / 平台管理员 | 将 `status` 改为 `off`，需填写下线原因；标签广场即时隐藏 | 已下线 |

#### 3.2.4 批量导入规则

| 规则项 | 规则 |
|---|---|
| 识别方式 | 以 `tag_id` 识别：平台中不存在为**新增**，已存在为**更新**（更新前展示字段差异） |
| 单次上限 | 每个文件最多 500 行 ❓ |
| 必填校验 | 3.2.1 中必填字段为空 → 该行报错 |
| 格式校验 | 覆盖率超出 0–100、枚举值不在范围、`tag_id` 含非法字符 → 报错 |
| 联动校验 | `timeliness = 1` 但 `update_freq` 为空或为「实时」→ 报错；`timeliness = 2` 时忽略填写值并自动置为「实时」并提示 |
| 存在性校验 | `owner` 非有效账号、`source_table` 或 `source_field` 不存在 → 报错 |
| 文件内重复 | 同一文件中 `tag_id` 重复 → 两行都报错 |
| 部分成功 | 校验通过的行可以先提交，错误行留在待修正列表 |
| 计算字段 | 文件中填写的 `effective_column_level` 忽略，由系统重新计算 |
| 导入记录 | 保留每次导入的文件、操作人、时间、新增 / 更新 / 失败条数，可追溯 |
