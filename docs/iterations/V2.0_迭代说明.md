## 3. 关键规则

- **标签状态**：当实时权限有效时，系统展示「可使用」；当存在审批中申请时，展示「已申请」且不可再申请；其余情况（含被拒绝、过期）展示「可申请」。
- **批量勾选**：仅列表视图提供，卡片视图不做勾选；只允许勾选「可申请」且不在清单中的标签；翻页或修改筛选时保留勾选；只能加入清单。
- **待选择清单**：当加入后超过 100 个时，超出部分不加入并提示；当勾选中包含不可申请标签时，「批量申请」置灰。
- **申请提交**：每个标签独立建单；若部分失败，只重试失败项；成功项自动移出清单。
- **资产接入**：当 `timeliness = 2` 时，更新频率固定为「实时」；当 `timeliness = 1` 时，更新频率必须为 T+1 / T+7；以 `tag_id` 区分新增和更新；所有提交先进入待审核。
- **圈人 Agent**：只有受控 / 高敏标签需要审批；当缺权限时，系统出现权限卡，不自动执行；当条件被修改且未重新执行时，结果面板提示当前展示的版本。
- **展示约束**：任何页面不展示枚举值、示例值、历史案例收益数值、申请单号。

完整规则见基线 PRD 第 7 章。

## 4. 本次不改什么

- 不在门户内落审批工单，审批仍在 Triton 完成。
- 不做审批方式、消费约束（允许场景、导出、脱敏、配额）配置。
- 不做每页条数 20 / 40 / 60 切换、到期提醒列出具体标签、「去使用」绿色、有效期橙 / 红色（放入 V2.1）。
- 圈人 Agent 不接真实 NL2SQL 与人群执行，不做策略知识库与 HTE 复盘。
- 资产审核上线后暂不同步到标签广场（需服务端统一资产数据）。
