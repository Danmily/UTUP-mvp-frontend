# 圈人 Agent MVP 功能表

| 功能点 | 入口与展现形态 | 功能设计 |
|---|---|---|
| **对话式圈人主流程** | 门户左侧菜单「圈人 Agent」进入；三栏布局：左侧栏（新建对话 / 圈人任务中心 / 策略知识库〔规划中〕/ 历史对话）+ 中间对话区 + 右侧结果面板 | 1. 用户用业务语言描述圈人目标，也可以点首页示例场景<br>2. 流程：描述需求 → 关键口径确认 → 圈选条件卡 → 权限校验 → 执行 → 结果<br>3. 每步的分析过程收在「查看分析过程 n/n」里，默认折叠<br>4. 底部输入框可以继续调整（如「改成窄口径」「目标规模 5 万人」），每次调整生成新版本<br>5. 一期只圈人，不投放 |
| **关键口径确认** | 对话流中的「关键口径确认」卡片，提交需求后自动出现 | 1. 只追问会改变入选范围的口径，原话里已经说清楚的不重复问<br>2. 每个问题附一句「为什么要问」，用户点选项回答<br>3. 全部选好后，点「确认口径，生成条件」 |
| **圈选条件卡** | 对话流中的「圈选条件」卡片，口径确认后出现 | 1. 条件分三组：必须满足（AND）/ 任一满足（OR）/ 排除（NOT），每条写明标签名和取值<br>2. 宽口径 / 窄口径二选一，各自显示预估人数<br>3. 目标规模选填，超出时按偏好分截取<br>4. 种子人群校验开关；可查看相关 SQL<br>5. 可删除条件；点「确认并执行」后条件锁定，并标注版本号 |
| **权限校验与一键申请** | 对话流中的「N 个标签权限待申请」卡片，在确认执行之后、真正执行之前出现 | 1. 权限判定和门户一致；只有受控、高敏级别的标签需要审批<br>2. 逐个列出缺权限的标签：标签名、密级、来源表、本次用途、当前状态<br>3. 「一键申请权限」：带入门户待选择清单；提交后可以返回原对话继续<br>4. 「使用其他标签」：换成可以直接用的标签，没有可替代的就去掉该条件，生成新版本条件 |
| **接入用户理解 Agent（生成 SQL）** | 没有单独入口，执行时在后台自动调用；对话中显示为「执行完成」里的「生成圈选 SQL」一步 | 1. 圈人 Agent 把确认后的口径和条件，整理成用户理解 Agent 需要的输入<br>2. 用户理解 Agent 根据条件生成 SQL<br>3. 生成的 SQL 可以在结果面板「相关 SQL」页查看 |
| **人群执行** | 没有单独入口；对话中显示为「执行完成 3/3」：生成圈选 SQL / 圈选人群 / 同步人群报告数据，每一步都能点开右侧面板 | 1. 在数据平台执行 SQL，产出人群包（执行平台待确认）<br>2. 结果绑定条件版本；修改条件后要重新执行<br>3. 执行失败时保留条件，提示原因，可以重试 |
| **结果展示** | 对话中的「人群包」结果卡，点开后在右侧打开结果面板（可全屏、可关闭） | 1. 结果卡：人群规模、口径、版本；人群报告异步生成<br>2. 结果面板 6 个标签页：人群明细（脱敏样例）/ 人群概览 / 圈选条件 / 相关 SQL / 人群报告 / 效果回收<br>3. 条件修改但未重新执行时，面板顶部提示当前展示的是哪个版本 |
| **定期更新** | 结果面板顶部的「定期更新」开关，下方常驻说明文字 | 1. 开启后，每天 08:00 按当前版本条件重算，人群包 ID 不变<br>2. 条件修改或标签权限失效时，暂停更新，并在对话中提醒 |
| **效果回收** | 结果面板「效果回收」页；对话中的「效果回收」快捷按钮 | 1. 用户回填核心指标、结论、LR 文档链接，和条件版本绑定<br>2. 不展示历史案例的收益数值 |
| **保存为模板** | 对话中的「保存为模板」快捷按钮；在「圈人任务中心」查看和复用 | 1. 结果出来后，可以把需求、条件、结果一起保存成模板<br>2. 后续相似需求可以直接复用模板，重新执行 |
